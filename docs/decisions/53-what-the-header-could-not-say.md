## The ask

The pack 0.18 study ended with four things the pack could not do alone:
1. **Case 9, session context.** A stack whose own header is silent, such as a GE susceptibility image written ORIGINAL, can be decided from the other series of its session. The research: only as a flagged secondary rule, certified separately, never overriding a series' own explicit header.
2. **Case 22 and case 16.** The fingerprint carries none of the MR Pulse Sequence module (PS3.3 C.8.13.4) and no SOP class, so the standard's mapping table cannot run, and an MR Spectroscopy Storage object cannot be told from a planning image named for one.
3. **The private elements the pack reads** (GE's pulse sequence name, Philips' scanning technique and diffusion direction) are not in the header packets raters and the replay read, so a packet replay counts those rules as absent.
4. **The `epimix_fallback` border** reads one value, so a NeuroMix winner, which 0.18.0 took apart from EPIMix, raises nothing.

## Rulings I propose

| | Proposal |
|---|---|
| R1 | **Session context is a pass, not a rule.** A pass of kind `session_context` runs after the rules and before the disposition. Only a rule the pack declares in such a pass reads the session; no rule set ever sees another stack |
| R2 | **A sibling is seen by its header alone.** The other stacks of the same study, through the fields the pass names (`session.sibling_fields`), a related series number, the same geometry and the same frame of reference, never by what a rule or a person decided of them. So the answer does not depend on the order stacks were classified in, and a packet that carries those fields replays it exactly. The loader refuses a sibling condition that reads anything else, through any flag, parser or derived text |
| R3 | **It never replaces what the header states.** A value a header tier decided (exclusive, combination, alternative, physics: flags and numbers the scanner wrote), a person's answer and a decision stay, whatever the pack says. A value read from the name, inferred by a longhand rule, defaulted or voted may be replaced, only at or below the pass's `replaces_at_most`. A rule whose answer would change a protected axis changes nothing and is counted as held. This is the engine's, not a knob |
| R4 | **It is flagged and certified apart.** Every value it writes has tier and basis `session`; its evidence names the pass, the rule and the sibling stacks by id. MRI pack 0.19.0 writes at 0.65, below the review threshold of 0.70, so each answer is also a review item (`<axis>:session`) and no session answer is ever "sure" in record 48's sense. A grade reports cells whose value in force has basis `session` as their own line, and the certificate's "from the header alone" excludes them; System 1 does not learn from them as header labels |
| R5 | **The mechanism attributes are the strongest evidence where present.** The research's order (module attributes before Siemens' stem, GE's PSD, ScanningSequence and words) holds. Each attribute reaches the flag the technique axis already reads, so a classic image, which writes none, reads exactly as before |
| R6 | **What a rater sees of the private elements is an allowlist, in the pack.** `private.shown` names ingested elements of a technical kind; the loader refuses any other, and the engine refuses every element of an identification block whatever a pack says. A value shaped like an identifier is withheld when it is shown |
| R7 | **`epimix_fallback` names both EPIMix and NeuroMix.** The border keeps v0's name; its note says which the winner held |

R1 to R4 follow the research's recommendation for case 9 with one choice of mine for Nima to confirm: R3 lets a session answer replace a value read from the **name**. The research says "never override a series' own explicit header". I read a name like `Ax SWAN` as explicit about the acquisition and silent about which of its outputs a stack is, which is the one question the session answers; without this, the one rule below could never act, because the SWI route reads the provenance from the name at 0.85. The flags and numbers the scanner wrote are never replaced.

### S2 · The session pass (kineuro/nils#325)

**Changes:**
1. `nils_pack::session`: the kind, and `decide`, the one function the engine and a replay call.
2. The loader (pack contract 8): `kind: session_context`, `phase: after` only; `target.when` and each rule's `when` read what a rule reads; `session.sibling_fields` (fields of the fingerprint and ingested private elements, never a derived text) and `replaces_at_most`; each rule's `sibling` (`series_number: {within, family}`, `same`, `same_frame_of_reference`, `own_series`, `when`), `require: some | none`, `set` (class-phase axes only, values checked against the vocabulary), `confidence`, `why`, `sources`. ### S3 · The private elements in the reader and in packets (kineuro/nils#325 loader, kineuro/nils#326 the rest)

**Changes:**
1. `private.shown` in a pack's private file (contract 8): each a `name` and a `why`. The loader refuses a name that is not ingested, one whose ingest entry is not of kind parameter, diffusion, timing, geometry or reconstruction (so `unknown` and unkinded entries are never shown), and one at an identification block: group 0009, a creator containing `IDEN`, Siemens CSA and MEDCOM headers, SIENET, SPI and GE's scanner study id (0043,xx62).

## Risks

- **For Nima, R3:** a session answer may replace a value read from the name, at or below the pass's bound. Without it the one rule never acts. If Nima reads the research's "explicit header" as including the name, I set the MRI pass's bound to 0.7 and drop the provenance from its `set`, which leaves provenance SWIRecon beside construct Magnitude on the stacks it moves.
- **The case 9 rule is written from GE's convention, not counted.** The counts (`empirical-conventions.md`) say the session separates a silent stack from its siblings by header on 63 of 756, and that on 659 the siblings look the same; they do not say how many silent SWAN images have a prefixed sibling of the same geometry and frame. Before the pack is released, the research role counts on the unsealed archive how many stacks the rule moves, and reads a sample of them; every answer is a review item until then. The certificate reports the rule's cells apart (R4), and System 1 round 8's label export must drop basis `session`.
- **Case 22 acts only after a re-read.** Until the Philips (and any other enhanced) series are read again, the new columns are empty and 0.19.0 reads the enhanced objects as 0.18.0 did. The research's own confidence for the table is high, but which attributes our scanners fill is unknown (the empirical study could not read the files): the re-read's report should count, per scanner model, the objects that fill each attribute before the reclassify.
- **The table can disagree with a name.** Where an enhanced object states the module, its technique follows the module even against a vendor word. That is the research's order, and it may move stacks that a reference settled by the name; the correction record by rule should gain a group for it if the first grade after the re-read shows such cells.
- **A sibling's frame of reference.** GE's computed outputs are expected to share the acquisition's frame; if a scanner or a workstation writes a new one, the rule is silent there, which is the safe side.
- **Stacked pull requests.** kineuro/nils#325 is based on kineuro/nils#324's branch and kineuro/nils#326 on kineuro/nils#325's. Merge them in order, retargeting the next to main before a merged branch is deleted, so GitHub does not close it.
- **The private elements a rater now sees** are six technical values, allowlisted and shape-checked. The allowlist lives in the pack, which a site can amend only through a pack version, not an overlay. A new vendor block of unknown content can only be shown by naming it, of a technical kind, in a new pack version that a person reviews.
- **Nothing ran on production or on the development laptop's own install.** Every test ran on scratch registries with `HOME`, `XDG_CONFIG_HOME` and `TMPDIR` under the worktrees' `engine/target` and the real toolchain, Postgres in the local test container. The replay check read only the development packets on the development laptop.

## After review (2026-09-30)

**R3 is ruled as written.** Nima rules R3 as I proposed it: a session answer may replace a value read from the name, at or below the pass's bound (0.85 in MRI pack 0.19.0), and never one that a header flag or number, a person or a decision set. This follows decision [48](48-the-reader-and-two-learners.md)'s rule that the scanner's fields outrank the site's names: the name is the site's, the flags and numbers are the scanner's. The fallback in "Risks" (a bound of 0.7 and no provenance in `set`) is not taken.

**Tightened in review, before merge** (a fifth commit on kineuro/nils#325):
1. **The tier protects an axis, not its values.** `InForce::replaceable` took an axis decided to nothing as undecided whatever its tier, so a person's answer of none, a decision to none or a header rule that decided nothing could be replaced by a session answer. Now only an axis that no tier decided counts as empty; every other axis is replaceable only by its tier and the bound. The unit test covers each protected tier deciding nothing.
2. **Every session answer is evidence and a question, whatever the pass's `emit` says.** R4 was the MRI pack's choice (0.65 below a threshold of 0.70); the engine now writes the evidence row and the `<axis>:session` review item for every value a session pass writes. The spec, the CHANGELOG and the review-item contract's kind table say so.
3. **The MRI session target requires a SWAN name.** Without it, an unprefixed GE image named for QSM or susceptibility that the SWI route left at its fallback could be read as a SWAN magnitude beside a `SWI:` output. An unprefixed GE image named SWI was already the route's own `ge_magnitude`. Tested with `Ax QSM 3D` and `Ax susceptibility`.
4. **A shown value holding a date written with separators is withheld** (`2026-09-30`, `30.09.2026`, `2026/9/30`), as eight digits already were. S3 change 2's list gains this shape.
